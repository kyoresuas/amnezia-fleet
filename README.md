# Amnezia Fleet

[![Go](https://img.shields.io/badge/Go-1.25-00ADD8?logo=go&logoColor=white)](https://go.dev/)
[![AmneziaWG](https://img.shields.io/badge/AmneziaWG-3.1-0f766e)](https://github.com/amnezia-vpn/amneziawg-linux-kernel-module)
[![PostgreSQL](https://img.shields.io/badge/PostgreSQL-17-4169E1?logo=postgresql&logoColor=white)](https://www.postgresql.org/)
[![ClickHouse](https://img.shields.io/badge/ClickHouse-25.8-FFCC01?logo=clickhouse&logoColor=black)](https://clickhouse.com/)

**Self-hosted control plane для AmneziaWG 3.1.** Один конфиг работает на нескольких серверах сразу: если IP заблокировали, домен переключается на другой адрес или другой сервер, а ключи пользователей остаются прежними. Плюс учёт трафика: сколько потратил каждый пользователь и на какие домены.

Работает с официальными клиентами Amnezia, свой клиент не нужен.

[Как это работает](#как-это-работает) · [Быстрый старт](#быстрый-старт) · [Маршруты API](#маршруты-api) · [Вопросы](#вопросы)

## Возможности

| Возможность | Что она даёт |
| --- | --- |
| Кластер вместо сервера | Один ключ, одни параметры обфускации и одна подсеть на любом числе узлов |
| Смена IP без перевыпуска | Конфиг содержит домен, адреса за ним меняются автоматически или вручную |
| Запасные IP | У узла может быть несколько адресов, в DNS светится только один |
| Определение блокировок | Проба из нужной страны делает настоящее рукопожатие AWG и отличает блокировку от аварии |
| Учёт трафика | Потребление по пользователям и устройствам, назначения по доменам и IP:порт, журнал DNS |
| Лимиты и сроки | Месячный лимит трафика и дата окончания, пиры снимаются с узлов автоматически |
| Конфиги | Ссылка `vpn://` для клиента Amnezia и `.conf` для AmneziaWG |
| Ядро | Узлы работают на модуле ядра amneziawg, управление через generic netlink без перезапуска интерфейса |

## Как это работает

```text
             Админ · Бот · Биллинг
                      │ HTTPS + токен
   ┌──────────── fleetd (control plane) ────────────┐
   │ PostgreSQL: кластеры, узлы, адреса, пользователи│
   │ ClickHouse: трафик, потоки, DNS                 │
   │ DNS-провайдер: A-записи домена кластера         │
   └───────┬──────────────────┬──────────────────┬───┘
     long-poll + отчёты       │            результаты проб
           │                  │                  │
   fleet-agent (узел 1)  fleet-agent (узел 2)  fleet-probe (РФ)
   amneziawg, NAT, DNS   amneziawg, NAT, DNS   рукопожатие с каждым IP
```

**Кластер** это логический сервер: приватный ключ, профиль обфускации AWG 3.1, подсеть и домен. Узлы кластера держат одинаковый интерфейс с одинаковыми пирами, поэтому клиент с одним конфигом подключится к любому из них. Сессия не привязана к IP сервера, на новом узле клиент просто делает новое рукопожатие.

**Клиент Amnezia** резолвит домен при каждом новом подключении. Поменяли A-запись, и следующий коннект уйдёт на новый адрес без перевыпуска конфига. Внутри живой сессии клиент адрес не меняет: при блокировке пользователь переподключается сам или это делает Always-on.

**Агент** на узле получает желаемое состояние long-poll'ом и применяет только разницу: новые пиры добавляются, удалённые снимаются, остальные сессии не рвутся. Состояние сохраняется на диск, поэтому узел работает и при недоступном control plane.

**Проба** раз в 30 секунд делает настоящее рукопожатие с каждым адресом теми же параметрами, что у клиентов. Если агент узла жив, а проба три раза подряд не достучалась, адрес помечается `blocked` и домен переезжает на следующий.

## Требования

| Компонент | Требования |
| --- | --- |
| Узел | Ubuntu 22.04+, root. Модуль ставится из PPA `amnezia/ppa` через DKMS, проверено на 24.04 с ядром 6.8 |
| Control plane | Docker и Docker Compose, от 2 ГБ памяти (ClickHouse) |
| Проба | Любая машина в стране пользователей, root не нужен |
| DNS | Cloudflare для автоматического переключения, иначе режим «только журнал» |

## Быстрый старт

### Control plane

```bash
cd deploy/control-plane
cp .env.example .env
# заполните FLEET_API_DOMAIN, пароли, FLEET_MASTER_KEY и FLEET_ADMIN_TOKEN
docker compose up -d --build
```

API будет доступен на `https://FLEET_API_DOMAIN` с сертификатом от Let's Encrypt. `FLEET_MASTER_KEY` шифрует ключи в базе: если его потерять, придётся перевыпускать все конфиги.

### Кластер и узлы

```bash
API=https://fleet.example.com/api/v1
AUTH="Authorization: Bearer $FLEET_ADMIN_TOKEN"

# кластер: ключ и параметры обфускации генерируются автоматически
curl -H "$AUTH" -X POST $API/clusters -d '{"name":"nl","hostname":"nl.vpn.example.com"}'

# узел: первый адрес активный, остальные запасные
curl -H "$AUTH" -X POST $API/clusters/<cluster_id>/nodes \
  -d '{"name":"nl-1","addresses":["203.0.113.10","203.0.113.11"]}'
```

В ответе будет `agent_token`, он показывается один раз. Установка узла:

```bash
make agent
scp bin/fleet-agent deploy/node/* root@203.0.113.10:/root/
ssh root@203.0.113.10 'FLEET_SERVER_URL=https://fleet.example.com FLEET_AGENT_TOKEN=<token> /root/install-node.sh /root/fleet-agent'
```

Скрипт ставит модуль ядра, nftables и systemd-юнит. Агент создаёт интерфейс `awgf0` и свою таблицу nftables, чужие правила, Docker и официальный контейнер Amnezia не трогает.

### Пользователь и конфиг

```bash
curl -H "$AUTH" -X POST $API/users -d '{"name":"ivan","traffic_limit_bytes":107374182400}'
curl -H "$AUTH" -X POST $API/users/<user_id>/peers -d '{"cluster_id":"<cluster_id>","name":"iphone"}'

# ссылка для клиента Amnezia
curl -H "$AUTH" "$API/peers/<peer_id>/config?format=amnezia"
# файл для AmneziaWG
curl -H "$AUTH" "$API/peers/<peer_id>/config?format=conf" -o ivan.conf
```

### Проба

```bash
curl -H "$AUTH" -X POST $API/probes -d '{"name":"msk-1","region":"ru"}'
```

В ответе `private_key` и `token`, оба показываются один раз. На машине в РФ:

```bash
FLEET_SERVER_URL=https://fleet.example.com FLEET_PROBE_TOKEN=<token> FLEET_PROBE_PRIVATE_KEY=<key> ./fleet-probe
```

## Маршруты API

Все маршруты `/api/v1` требуют `Authorization: Bearer <FLEET_ADMIN_TOKEN>`.

| Метод | Путь | Что делает |
| --- | --- | --- |
| `GET` `POST` | `/clusters` | Список и создание кластеров |
| `GET` `PATCH` `DELETE` | `/clusters/{id}` | Кластер; менять можно только то, что не ломает выданные конфиги |
| `GET` | `/clusters/{id}/dns` | Что сейчас опубликовано в DNS |
| `POST` | `/clusters/{id}/dns/sync` | Пересчитать и опубликовать DNS сейчас |
| `GET` | `/clusters/{id}/online` | Кто подключён прямо сейчас и к какому узлу |
| `GET` `POST` | `/clusters/{id}/nodes` | Узлы кластера, регистрация узла |
| `GET` `PATCH` `DELETE` | `/nodes/{id}` | Узел; `state`: `active`, `draining`, `disabled` |
| `POST` | `/nodes/{id}/token` | Новый токен агента |
| `POST` | `/nodes/{id}/addresses` | Добавить адрес узлу |
| `PATCH` `DELETE` | `/addresses/{id}` | `state`: `active`, `spare`, `blocked`, `disabled`, и приоритет |
| `GET` `POST` | `/users` | Пользователи |
| `GET` `PATCH` `DELETE` | `/users/{id}` | Статус, лимит трафика, срок |
| `GET` `POST` | `/users/{id}/peers` | Устройства пользователя |
| `GET` `PATCH` `DELETE` | `/peers/{id}` | Устройство, `enabled` |
| `GET` | `/peers/{id}/config` | `format=amnezia` или `format=conf` |
| `GET` `POST` `DELETE` | `/probes` | Пробы |
| `GET` | `/probes/status` | Последние результаты проб |
| `GET` | `/stats/usage` | Трафик всех устройств за период |
| `GET` | `/users/{id}/usage` | Временной ряд трафика, `step` в секундах |
| `GET` | `/users/{id}/destinations` | Куда уходит трафик, `by=domain` или `by=ip` |
| `GET` | `/users/{id}/dns` | Журнал DNS-запросов |
| `GET` | `/events` | Журнал: смены DNS, блокировки, ошибки агентов |

Периоды задаются `from` и `to` в RFC 3339, по умолчанию с начала месяца.

## Переключение адресов

Каждый адрес узла имеет состояние и здоровье.

| Состояние | Что значит |
| --- | --- |
| `active` | Можно публиковать в DNS |
| `spare` | Запасной, публикуется, только если активных не осталось |
| `blocked` | Заблокирован: пробой или вручную. Проба продолжает его проверять |
| `disabled` | Выведен из ротации |

Режим `failover` (по умолчанию) держит в DNS один адрес и не меняет его, пока тот жив. Так запасные IP не попадают в DNS раньше времени, и цензору нечего собрать заранее. Режим `all` публикует все живые адреса.

На тестовом стенде с проверкой раз в 15 секунд блокировка определялась и домен переключался примерно за 75 секунд. Разблокированный адрес сам в DNS не возвращается: событие в журнале подскажет, что его можно вернуть через `PATCH /addresses/{id}`.

## Учёт трафика

| Данные | Откуда | Хранится |
| --- | --- | --- |
| Байты по устройствам | Счётчики пиров в ядре | 400 дней |
| Назначения: IP, порт, протокол, домен | conntrack | 90 дней |
| DNS-запросы | Резолвер агента на шлюзе туннеля | 30 дней |

Домены видны, когда клиент резолвит имена через DNS узла: по умолчанию в конфиге стоит адрес шлюза `10.66.0.1`. Если в браузере включён DNS-over-HTTPS, трафик всё равно учитывается по IP, но без имени домена.

## Безопасность

- Агенты получают приватный ключ кластера, поэтому API публикуется только через HTTPS.
- Приватные ключи в базе зашифрованы AES-256-GCM мастер-ключом, токены хранятся хешами.
- Клиенты изолированы друг от друга и не видят приватные сети узла, включая Docker-контейнеры.
- DNS-резолвер отвечает только клиентам туннеля.
- Один ключ на кластер означает, что взлом одного узла раскрывает ключ всего кластера. Узлы с разным уровнем доверия держите в разных кластерах.

## Вопросы

### Переключится ли клиент на другой сервер прямо во время сессии?

Нет. Официальный клиент Amnezia резолвит домен только при подключении, внутри сессии адрес не меняется. При блокировке соединение пропадёт, пользователь переподключится и попадёт на новый адрес.

### Что если заблокируют сам домен?

Выдайте домен в другой зоне и пересоздайте конфиги, это единственный случай, когда нужен перевыпуск. Ключи и адреса пиров при этом можно оставить прежними.

### Можно ли без ClickHouse?

Да, без `FLEET_CLICKHOUSE_URL` всё работает, кроме учёта трафика и месячных лимитов.

### Почему проба должна стоять в России?

Блокировка видна только изнутри. Проба за границей увидит, что сервер жив, и ничего не переключит.

## Разработка

```bash
make vet     # go vet для macOS и Linux
make build   # fleetd, fleet-agent (linux/amd64), fleet-probe в bin/
```

Агент собирается только под Linux. Для ARM-серверов: `GOARCH=arm64 make agent`.
